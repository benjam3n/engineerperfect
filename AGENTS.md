# Contributing to engineerperfect

The current user request governs. Engineerperfect covers the literal practice of engineering, the broader act of arranging worthwhile conditions, improvement of engineering itself, and the engineer's actual capabilities. Preserve that scope while letting evidence change the interpretation, target, mechanism, or criterion of a particular inquiry.

Read the relevant existing result before extending it. The repository comparison and pinned source record distinguish prior work from additions here. Do not present inherited distinctions, familiar engineering methods, or imported results as new discoveries.

Supply the requested construction, comparison, derivation, intervention, or exact conditional result. If a central operation is named but not supplied, implement or perform it when possible. If a missing parameter permits a symbolic answer, derive that answer. An unavailable observation may limit a claim; it does not excuse omitting consequences already entailed by the available facts.

When a live weakness concerns consequence construction, capability construction, alternatives, or correction uptake, use the relevant Subject System already identified in the pinned mindchangeresearch instructions. Perform its missing contribution or reuse a justified applicable result. Naming the system does not satisfy this requirement. Original RSI/Reasoningtool procedures require their own original sources if explicitly invoked; no original-skill execution is implied here.

Use actual subject names and direct findings. A heading, schema, repeated reflection paragraph, priority number, or placeholder phrase cannot stand in for the missing judgment. Organize by the relations and uses the material actually supports. Keep sources and verification accounting out of the main argument except where they establish an essential claim.

Separate a worthwhile requirement, a feasible mechanism, faithful execution, observed effect, continued maintenance, and transfer. A passing test establishes the property tested. An empty action or successor set cannot become a successful control action through vacuous logic. No automatically assigned KEEP or completion count replaces inspection of the supplied product and its obligation.

Count support resources, production prerequisites, time, repair, and recipient effort where they affect the undertaking. Identify a model boundary without making that boundary a universal limit on engineering. A change of criterion or admitted conditions changes the claim; preserve the original obligation when it remains live.

Correct actual producers and dependent uses when a demonstrated defect is found. Retain meaningful failed constructions and counterexamples with the premises that produced them. Do not continue generating or testing after the requested work is complete unless another concrete unresolved risk requires it.

For this implementation, run the example calculation and the finite-control checks when relevant code or assumptions change. The examples are stipulated models, not empirical interventions. Do not claim field performance, changes in a person's mind, or improved general model capability without the appropriate observations.
